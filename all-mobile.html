1. Overstrike

Godot 4 + .NET Reversão de PRNG Flag confirmada

O jogo mantém um selo do mundo (WorldSeal) derivado de uma marca carregada pelo jogador (CarriedMark) através de uma função Mix. Quando o selo bate com uma constante TrueSeal, o registro cifrado é aberto. A função Mix é um SplitMix64 puro — e SplitMix64 é bijetivo, logo a marca correta é obtida invertendo a constante.

7Inverter o SplitMix64 e recuperar a CarriedMark

Os multiplicadores são invertidos por exponenciação modular; o x ^= x >> k é desfeito iterando o próprio xorshift (8 iterações cobrem 64 bits com folga).

Comando
python3 - <<'EOF'
M = (1 << 64) - 1

def undo_xor_right(v, s):
    r = v
    for _ in range(8):
        r = v ^ (r >> s)
    return r & M

def inverse_splitmix64(v):
    v = undo_xor_right(v, 31)
    v = (v * pow(0x94D049BB133111EB, -1, 1 << 64)) & M
    v = undo_xor_right(v, 27)
    v = (v * pow(0xBF58476D1CE4E5B9, -1, 1 << 64)) & M
    v = undo_xor_right(v, 30)
    return (v - 0x9E3779B97F4A7C15) & M

def mix(x):
    x = (x + 0x9E3779B97F4A7C15) & M
    x = ((x ^ (x >> 30)) * 0xBF58476D1CE4E5B9) & M
    x = ((x ^ (x >> 27)) * 0x94D049BB133111EB) & M
    return x ^ (x >> 31)

print("inv mult 1 =", hex(pow(0xBF58476D1CE4E5B9, -1, 1 << 64)))
print("inv mult 2 =", hex(pow(0x94D049BB133111EB, -1, 1 << 64)))
cm = inverse_splitmix64(0xD9A1BB0CABB52586)
print("CarriedMark =", hex(cm))
print("round-trip  =", hex(mix(cm)), mix(cm) == 0xD9A1BB0CABB52586)
EOF

4Recuperar a tabela de identificadores (offline, sem GDRE)

Após o zstd, o buffer traz 4 uint32 de cabeçalho e então a tabela de identificadores, com cada caractere gravado como uint32 XOR 0xB6B6B6B6. Isso já entrega o esqueleto de cada script sem nenhuma ferramenta externa.

Comando
cat > re/gdc_ident.py <<'PY'
#!/usr/bin/env python3
"""Recupera a tabela de identificadores de um .gdc (GDScript 4 bytecode)."""
import struct, sys, zstandard

raw = open(sys.argv[1], "rb").read()
assert raw[:4] == b"GDSC", "nao e um .gdc"
buf = zstandard.ZstdDecompressor().decompress(raw[12:], max_output_size=1 << 22)

n_ident = struct.unpack_from("<I", buf, 0)[0]
off = 16
for _ in range(n_ident):
    (length,) = struct.unpack_from("<I", buf, off); off += 4
    chars = struct.unpack_from(f"<{length}I", buf, off); off += 4 * length
    print("".join(chr(c ^ 0xB6B6B6B6) for c in chars))
PY

    2085:	xor    $0xa5a5a5a5,%eax           ; invalido -> embaralha o retorno

Dois motivos independentes tornam (83, 67, 55, 462) impossível pelo jogo:

  • o clampi(..., 0, 24) em file_ward — e o cmp $0x18 nativo — limitam cada ward a 24, mas o alvo exige 83, 67 e 55;
  • a fórmula do bite daria 83 + 2·67 + 3·55 = 382, e não 462.

Consequência prática: o hallmark devolvido pelo jogo para esse estado seria embaralhado no ramo 0x2085. O valor que submit() espera é o resultado bruto da VM, lido em 0x2054 antes dessa validação. É exatamente aí que a emulação entra.

import struct
from pathlib import Path
from elftools.elf.elffile import ELFFile
from unicorn import Uc, UC_ARCH_X86, UC_HOOK_CODE, UC_MODE_64
from unicorn.x86_const import (UC_X86_REG_EAX, UC_X86_REG_RDI,
                               UC_X86_REG_RSI, UC_X86_REG_RSP)

RESEAL_ADDRESS, RAW_RESULT_ADDRESS = 0x1C10, 0x2054
lib = Path('work/proof/lib/x86_64/libproofmark.x86_64.so')

uc = Uc(UC_ARCH_X86, UC_MODE_64)
uc.mem_map(0, 0x10000)
with lib.open('rb') as fh:
    for seg in ELFFile(fh).iter_segments():
        if seg['p_type'] == 'PT_LOAD' and seg['p_filesz']:
            uc.mem_write(seg['p_vaddr'], seg.data())
uc.mem_map(0x70000000, 0x20000)
uc.mem_map(0x71000000, 0x1000)

state = struct.pack('<4I', 83, 67, 55, 462)
uc.mem_write(0x71000000, state)
uc.reg_write(UC_X86_REG_RSP, 0x70010000)
uc.reg_write(UC_X86_REG_RDI, 0x71000000)
uc.reg_write(UC_X86_REG_RSI, len(state))
uc.hook_add(UC_HOOK_CODE,
            lambda u, a, s, d: u.emu_stop() if a == RAW_RESULT_ADDRESS else None)
uc.emu_start(RESEAL_ADDRESS, RAW_RESULT_ADDRESS + 1, count=50_000_000)

9Determinar quais assentos mordem

ShardSeat.Bites depende da geometria em Tolerances: ChokeZ(i) = 14 − 6i, e a meia-largura da coluna interpolada entre 9.5 e 5.2 tem de caber em MaxBitingHalfWidth = 8.1.

Comando

inv_lerp = lambda a, b, v: (v - a) / (b - a)
lerp     = lambda a, b, t: a + (b - a) * t
for i in range(8):
    z  = 14 - 6 * i                                  # Tolerances.ChokeZ
    t  = min(max(inv_lerp(14, -40, z), 0.0), 1.0)    # Tolerances.HalfWidthAt
    hw = lerp(9.5, 5.2, t)
    print(f"choke {i}: z={z:6.1f}  halfwidth={hw:6.3f}  bites={hw <= 8.1}")

Observações finais

O par Proofmark / SaltCrown é deliberado. As flags tru3_sp1n3 e wr0ng_sp1n3 partilham o prefixo p3rf3ct_f4c3: os dois desafios mostram a mesma face perfeita (uma UI que valida entradas) sobre espinhas opostas. Em Proofmark, a validação "correta" do jogo é justamente o que impede alcançar o estado premiado — a solução é ignorar a UI e falar direto com a biblioteca. Em SaltCrown, a geometria da cena é que decide silenciosamente o segredo.

Padrão recorrente da trilha. Nos três casos o segredo nunca aparece como literal HTB{...}: é sempre um blob curto (24, 28 ou 56 bytes) desfeito por um keystream barato derivado de um estado que o jogo deveria produzir. Achar o blob é fácil; o trabalho está em recuperar o estado — invertendo um PRNG bijetivo, emulando uma VM ou reimplementando uma esponja nativa.

Apêndice — solvers

  • Overstrike/solve.py — inverte o SplitMix64 e testa as variações de contador do keystream SHA-256.

  • SaltCrown/solve.py — reimplementa AshVault::admit_bucket e varre C(8,5).
